# Population thermal model training

This folder trains population-level thermal-sensation models from the teammate-prepared dataset. Personal calibration and personal bias are intentionally out of scope.

## Structure

- `data/processed/thermosurvey_prepared.csv` — prepared input (not modified)
- `notebooks/population_model_training.ipynb` — guided training and review notebook
- `notebooks/feature_engineering_experiments.ipynb` — training-only V1-V5 experiment report
- `train.py` — reproducible command-line training workflow
- `feature_experiment.py` — fixed-split feature experiment runner
- `src/feature_engineering.py` — leakage-safe V1-V5 preprocessing pipelines
- `results/` — evaluation tables and plots generated by training
- `artifacts/` — selected model, metadata, and training-domain limits generated by training
- `docs/feature_engineering_summary.md` — selection evidence, locked test result, and limitations
- `tests/` — small split, metric, and feature-transform checks

## Run from the repository root

```bash
python3 -m venv .venv
source .venv/bin/activate
python -m pip install -r ai/thermal_model/requirements.txt
python -m unittest ai/thermal_model/tests/test_train.py
python ai/thermal_model/train.py
python ai/thermal_model/feature_experiment.py
```

On macOS, install XGBoost's OpenMP runtime once before the Python requirements: `brew install libomp`.

Or open `ai/thermal_model/notebooks/population_model_training.ipynb` after installing the same requirements.

The script uses an 80/20 held-out split stratified by city and target class. Five-fold cross-validation, tuning, probability checks, per-city checks, and model selection use only the training split. The held-out split is used once for final overall and Warsaw/Madrid evaluation.

Generated files are reproducible from the prepared CSV and should not be edited by hand. The artifact metadata records features, classes, random seed, dependency versions, dataset hash, population-only scope, and min/max training-domain limits.
